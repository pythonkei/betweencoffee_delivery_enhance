# Between Coffee 訂購流程 vs 競品分析報告

> **最後更新**: 2026年7月15日
> **分析範圍**: 瑞幸咖啡、Manner Coffee、喜茶 — 使用者訂購流程邏輯比較

---

## 一、Between Coffee 現有訂購流程分析

### 1.1 整體流程圖

```
瀏覽菜單 → 選擇商品（咖啡/咖啡豆）→ 自定義選項 → 加入購物車
    ↓
滑出購物車（可修改數量/刪除）
    ↓
前往結帳（order_confirm 頁面）
    ↓
填寫聯絡資訊（姓名/電話/Email）
    ↓
選擇支付方式（PayPal/Alipay/FPS/現金）
    ↓
應用優惠券/積分獎勵
    ↓
提交訂單 → 購物車清空 → 跳轉支付
    ↓
支付完成 → 訂單確認頁面（顯示取餐碼、排隊狀態）
```

### 1.2 關鍵使用者體驗細節

| 環節 | 實作方式 | 使用者感受 |
|------|---------|-----------|
| **商品瀏覽** | 咖啡菜單 / 咖啡豆菜單 分開頁面 | 需切換頁面，無法一覽全部商品 |
| **加入購物車** | 商品詳情頁 → 自定義選項 → POST 加入 | 流程較長，需跳轉頁面 |
| **購物車** | 滑出抽屜式（420px 寬），支援數量增減/刪除 | 體驗流暢，不離開當前頁面 |
| **快速訂單** | 首頁一鍵下單（固定 WakeMeup 咖啡） | 簡潔快速，但僅限單一商品 |
| **結帳流程** | 兩步驟：order_confirm → 支付跳轉 | 步驟較多，需填寫聯絡資訊 |
| **支付方式** | 4 種（PayPal/Alipay/FPS/現金） | 選擇多樣，但 FPS/現金需手動確認 |
| **訂單狀態** | WebSocket 即時更新 + 進度條 | 即時性佳 |
| **取餐碼** | 訂單確認頁顯示取餐碼 | 方便取餐 |

### 1.3 現有流程的問題點

1. **商品瀏覽與購物車分離**：咖啡和咖啡豆分屬不同頁面，使用者需來回切換
2. **結帳步驟偏多**：需先到 order_confirm 頁面填寫資訊，再跳轉支付
3. **快速訂單功能有限**：僅支援固定商品（WakeMeup），無法自選
4. **無商品分類/篩選**：菜單頁面無分類標籤或篩選功能
5. **購物車 badge 同步問題**：從外部支付平台返回時 badge 可能未更新（已修復）

## 二、競品訂購流程比較

### 2.1 瑞幸咖啡（Luckin Coffee）

| 環節 | 流程 | 亮點 |
|------|------|------|
| **進入點** | App / 微信小程序 | 雙入口，小程序免安裝 |
| **商品瀏覽** | 首頁 = 點單頁面，商品分類清晰（熱銷/新品/分類標籤） | **一頁式瀏覽 + 點單** |
| **加入購物車** | 點選商品 → 選擇規格 → 直接加入購物車（不跳頁） | 無頁面跳轉 |
| **自定義** | 溫度（冰/熱）、杯型（中/大）、糖度、加料 | 選項豐富但直覺 |
| **購物車** | 底部浮動購物車欄，顯示數量 + 總價 | 常駐底部，隨時可見 |
| **結帳** | 點擊底部購物車 → 確認訂單 → 支付（**一頁完成**） | 極簡流程 |
| **AI 點單** | AI Lucky 智能體，支援自然語言點單 | 創新功能 |
| **取餐** | 顯示排隊杯數 + 預計等待時間 | 透明化排隊 |
| **優惠** | 自動匹配最優惠券，券後價格直接顯示 | 無需手動輸入 |

**核心優勢**：
- **首頁即點單頁**，瀏覽與購買零切換
- **底部常駐購物車**，隨時查看/修改
- **自動匹配優惠**，減少使用者思考
- **AI 語音/文字點單**，降低操作門檻

### 2.2 Manner Coffee

| 環節 | 流程 | 亮點 |
|------|------|------|
| **進入點** | 微信小程序 | 純小程序 |
| **商品瀏覽** | 分類標籤（意式/手沖/特調/單品豆）+ 列表 | 分類清晰 |
| **加入購物車** | 選擇商品 → 加入購物車 | 標準流程 |
| **自定義** | 溫度、杯量（小/中/大）、加濃、換燕麥奶 | 選項適中 |
| **購物車** | 獨立購物車頁面 | 傳統模式 |
| **結帳** | 購物車 → 確認 → 支付 | 標準三步驟 |
| **取餐** | 到店取餐（需現場排隊） | 系統較混亂 |
| **自帶杯** | 自帶杯減 $5 | 環保亮點 |

**核心優勢**：
- 價格親民（15-25 元）
- 自帶杯減 $5 的環保理念
- 分類標籤清晰

**已知問題**（根據新聞報導）：
- 線上線下訂單系統不同步
- 線上顯示已售罄，線下可點單
- 取餐需二次排隊
- 多平台資訊不一致

| 環節 | 流程 | 亮點 |

- **極致個性化自定義**（冰量 6 級、甜度 5 級、多種加料）
- **排隊透明化**（顯示前方杯數 + 預計時間）
- **數據驅動的千人千面推薦**

- **會員體系完善**

## 四、從使用者邏輯角度的關鍵洞察

### 4.1 使用者最在意的三件事

1. **快** — 從看到商品到完成支付，步驟越少越好
2. **透明** — 排隊狀態、等待時間、價格計算要清楚可見
3. **個人化** — 口味自定義、優惠自動匹配、歷史記錄

### 4.2 Between Coffee 可借鏡的改進方向

| 改進方向 | 參考對象 | 預期效益 |
|---------|---------|---------|
| **首頁即點單**（商品瀏覽 + 加入購物車在同一頁） | 瑞幸、喜茶 | 減少頁面跳轉，提升轉換率 |
| **底部常駐購物車欄**（顯示數量 + 總價） | 瑞幸、喜茶 | 購物車隨時可見，降低遺忘率 |
| **一頁式結帳**（商品確認 + 聯絡資訊 + 支付在同一頁） | 瑞幸 | 減少結帳步驟 |
| **排隊透明化增強**（顯示前方還有 N 杯） | 瑞幸、喜茶 | 減少等待焦慮 |
| **優惠自動匹配**（無需手動輸入優惠碼） | 瑞幸 | 提升轉換率 |
| **歷史訂單快速復購** | 瑞幸、喜茶 | 提升回購率 |
| **自定義選項優化**（更直覺的冰量/甜度選擇） | 喜茶 | 提升個人化體驗 |

### 4.3 Between Coffee 的獨特優勢（應保留）

1. **WebSocket 即時狀態更新** — 比瑞幸/喜茶的輪詢更即時
2. **多種支付方式**（PayPal/Alipay/FPS/現金）— 比競品更多元
3. **取餐碼系統** — 方便辨識
4. **滑出購物車** — 不離開當前頁面即可操作
5. **快速訂單**（一鍵下單）— 雖然功能有限，但方向正確

## 五、總結建議

### 短期可優化（低投入高回報）

1. **底部常駐購物車欄** — 參考瑞幸，在頁面底部顯示購物車摘要（數量 + 總價），點擊展開滑出抽屜
2. **一頁式結帳優化** — 將 order_confirm 的步驟整合到更少的頁面切換
3. **優惠自動匹配** — 後台設定優惠規則，結帳時自動應用最佳優惠

### 中期可規劃

4. **首頁即點單 redesign** — 將咖啡/咖啡豆菜單整合到同一頁面，加入分類標籤
5. **排隊透明化增強** — 在訂單確認頁顯示「前方還有 N 杯在製作」
6. **歷史訂單復購** — 一鍵重新下單上次的訂單

### 長期願景

7. **會員體系強化** — 參考喜茶的會員分級制度
8. **AI 輔助點單** — 參考瑞幸 AI Lucky，支援自然語言點單
